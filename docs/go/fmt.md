# Go 格式化动词（fmt / log 的 %d %s %v）

### 为什么需要

`log.Printf` / `fmt.Printf` 的第一个参数是格式串，里面的动词按**从左到右**的顺序，一对一吃掉后面的实参。数量对不上、类型对不上时，Go 不会报错，而是在输出里塞一段 `%!动词(类型=值)`。

### 一句话理解

动词是"你要我用什么形式打印这个值"，每个动词消费一个实参，顺序即对应关系。

### 常见动词

| 动词 | 用于 | 说明 |
|------|------|------|
| `%v` | 任意类型 | 默认格式，最省心 |
| `%+v` | struct | 带字段名，如 `{ID:doc1 Content:xxx}` |
| `%#v` | 任意 | Go 语法形式，如 `main.doc{ID:"doc1", ...}` |
| `%T` | 任意 | 值的**动态**类型 |
| `%d` | 整数 | 十进制 |
| `%s` | 字符串 / []byte | 原文 |
| `%q` | 字符串 | 加引号并转义控制字符，换行显示成 `\n` |
| `%t` | bool | |
| `%f` | 浮点 | `%.2f` 控制小数位 |
| `%p` | 指针 | 地址 |
| `%w` | error | 仅 `fmt.Errorf` 可用，用于包装错误 |

### 具体例子

以文档切分示例里这行为例（该 demo 已删除，逻辑并入了 `components/markdown.go` 和 `RAG/Rag.go`，例子保留）：

```go
log.Printf("片段 %d | id=%s | h1=%v h2=%v h3=%v", i, d.ID, d.MetaData["h1"], d.MetaData["h2"], d.MetaData["h3"])
```

对应关系：

| 动词 | 实参 | 静态类型 | 为什么用这个 |
|------|------|----------|--------------|
| `%d` | `i` | `int` | 循环下标是整数 |
| `%s` | `d.ID` | `string` | 就是字符串 |
| `%v` | `d.MetaData["h1"]` | `any` | 见下 |
| `%v` | `d.MetaData["h2"]` | `any` | 见下 |
| `%v` | `d.MetaData["h3"]` | `any` | 见下 |

### 为什么 metadata 用 %v 而不是 %s

`MetaData` 的类型是 `map[string]any`，取出来的是 `any`（接口），**静态类型不是 string**。两种情况会出问题：

1. key 不存在 → 拿到 nil 接口，`%s` 打印成 `%!s(<nil>)`
2. value 不是字符串（比如塞了个 int）→ `%!s(int=3)`

`%v` 对任意类型都成立，nil 就老老实实打印 `<nil>`。实测对比：

```text
h3=%v  →  h3=<nil>
h3=%s  →  h3=%!s(<nil>)
```

### 动词用错会怎样（实测）

```text
用 %d 打 string: %!d(string=doc1)
用 %s 打 int:    %!s(int=2)
```

不会 panic，也不会编译报错，只是输出里多一段垃圾——所以这类错误很容易在日志里被忽略。

### go vet 能查一部分

`go vet` 会检查 Printf 系列的格式串，但它只能看**静态类型**：

```text
fmt_verbs.go:23:34: fmt.Printf format %d has arg id of wrong type string
fmt_verbs.go:24:34: fmt.Printf format %s has arg i of wrong type int
```

`%d` 配 string、`%s` 配 int 都能查出来。但 `%s` 配 `map[string]any` 的值**查不出来**，因为 vet 不知道运行时里面装的是什么。这正是不该对 `any` 用 `%s` 的实际理由。

### 为什么不全用 %v

先澄清一个前提：`%v` 对 `int` / `string` / `bool` 的输出，和 `%d` / `%s` / `%t` **完全一样**。所以"全用 `%v`"不会让日志打错，丢掉的是下面三样东西，而且只在类型变复杂之后才暴露。

**1. 类型一复杂，输出就不可读**

| 值 | `%v` | 具体动词 |
|----|------|----------|
| `[]byte("hello")` | `[104 101 108 108 111]` | `%s` → `hello` |
| `1234567.0` | `1.234567e+06` | `%f` → `1234567.000000` |
| `0.0000012` | `1.2e-06` | `%f` → `0.000001` |
| `user{Name:"max", Age:26}` | `{max 26}` | `%+v` → `{Name:max Age:26}` |

`%v` 打 `[]byte` 给的是一串字节数字；打浮点用的是 `%g`（最短表示），会滑向科学计数法，金额和耗时这类数字最容易中招。`{max 26}` 这种输出的问题是信息不足——字段一多、或者两个字段类型相同，日志就没法读了。

**2. 类型一变，输出含义会悄悄变**

| 类型 | `%v` 输出 | 含义 |
|------|-----------|------|
| `time.Duration(1500 * time.Millisecond)` | `1.5s` | 人类可读 |
| 同一个值当成 `int64` | `1500000000` | 纳秒 |

`%v` 打 `Duration` 会走它的 `String()`。字段一旦被改成 `int64`，同一行日志变成 `1500000000`——还在正常输出，意思已经变了，而且没人会注意到。

`any` 同理：里面装 `int 42` 和装 `string "42"`，`%v` 都是 `42`，日志里分不出来；换成 `[]byte("42")` 又变成 `[52 50]`。

**3. `go vet` 无从下手**

如果整份代码全用 `%v`，vet 在格式串上除了数个数就没东西可查了，参数顺序写反、类型传错全部静默通过。写具体动词等于向编译器声明"这里必须是整数"，写错立刻被报出来。

### 选择规则

| 情况 | 用什么 |
|------|--------|
| 类型已知的标量（int / string / bool） | `%d` / `%s` / `%t` |
| 浮点、金额、耗时 | `%f` / `%.2f`，别交给 `%v` |
| `[]byte`、二进制、哈希 | `%s` 或 `%x`，不用 `%v` |
| 结构体调试 | `%+v`（要字段名）/ `%#v`（要类型和语法形态） |
| 需要看清空白、换行、不可见字符 | `%q` |
| 有 `String()` / `error` 的类型 | `%v`，这是惯例 |
| `any`、真的不知道类型 | `%v`，这是它不可替代的场合 |

> `%v` 的真实含义不是"通用格式"，而是"我不打算承诺这个值是什么类型"。类型明明知道却用 `%v`，丢掉的是可读性和可被工具检查的能力。

### 容易混淆

- **`%T` 给的是动态类型。** `meta["h1"]` 的静态类型是 `any`，但 `%T` 打印 `string`——因为里面实际装的是 string。想看静态类型得看声明。
- **动词数量少于实参**时，多余的实参会被打印成 `%!(EXTRA ...)`；动词多于实参时是 `%!动词(MISSING)`。
- **`%v` 打印切片**用空格连接元素。如果元素实现了 `String() string`，用的是那个方法的返回值——`[]*schema.Document` 打印出来像一坨就是这两条叠加的结果（见 `docs/eino/document.md`）。
- **`log.Printf` 和 `fmt.Printf` 的动词规则一样**，只是 log 会额外加时间前缀。

### 验证方式

```bash
go vet ./...          # 静态类型对不上的能查出来
gofmt -l .            # 格式问题
```
