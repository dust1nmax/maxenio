## 真正理解的知识

### 1. Markdown HeaderSplitter 的切分规则

顺着 Markdown 标题走，遇到标题开新片，并把标题路径写进 MetaData。869 字节的 `document.md` 被切成 10 片。

关键细节：标题紧挨标题时，会产生只有标题、没有正文的片（h1 那片就是这样），这是规则的自然结果。

### 2. `Document.String()` 只返回 Content

`eino@v0.9.19/schema/document.go:50`：

```go
func (d *Document) String() string {
	return d.Content
}
```

这解释了为什么 `fmt.Println(splitDocs)` 打印出来像"一整块没切开"——切片元素用空格连接，把 10 片连成了一条。

### 3. 切片默认共用原文档 ID

`header.go:32` 的 `defaultIDGenerator` 直接返回原 ID，所以 10 片全是 `doc1`。入库 Milvus 时会主键冲突互相覆盖，必须自己配 `IDGenerator`。

### 4. 空行会被 splitter 丢掉

`splitText` 里 `if len(line) == 0 { continue }`，每行还要 `strings.TrimSpace`。所以片内不保留空行和缩进。

### 5. 格式化动词和实参是一对一、按顺序对应的

```go
log.Printf("片段 %d | id=%s | h1=%v h2=%v h3=%v", i, d.ID,
	d.MetaData["h1"], d.MetaData["h2"], d.MetaData["h3"])
```

| 动词 | 实参 | 静态类型 |
|------|------|----------|
| `%d` | `i` | `int` |
| `%s` | `d.ID` | `string` |
| 三个 `%v` | `d.MetaData["h1"/"h2"/"h3"]` | `any` |

metadata 那三个必须用 `%v`：`MetaData` 是 `map[string]any`，取出来是 `any`，key 不存在时是 nil 接口。实测 `%s` 会打出 `%!s(<nil>)`，而 `%v` 干净地打印 `<nil>`。

动词用错不会 panic，只在输出里塞垃圾：`%d` 配 string 得到 `%!d(string=doc1)`，`%s` 配 int 得到 `%!s(int=2)`。

`go vet` 能查出 `%d` 配 string 这类静态类型不匹配，但**查不出** `%s` 配 `map[string]any` 的值——vet 不知道运行时装的是什么。这就是不该对 `any` 用 `%s` 的实际理由。

接着追问了"`%v` 既然是任意类型，为什么不都用 `%v`"。答案是：对 `int`/`string` 这类基本类型，`%v` 和 `%d`/`%s` 输出**完全一样**，所以不会打错，但会丢掉三样东西——类型复杂后输出不可读（`[]byte` 变成字节数字、浮点滑向 `1.2e-06`）、类型变化时输出含义悄悄改变（`Duration` 从 `1.5s` 变成 `1500000000`）、`go vet` 无从下手。结论：类型明确就用具体动词，`%v` 留给 `any` 和不确定的场合。

## 遇到的问题

### 问题 1：程序输出看起来没有切分

**现象**：`fmt.Println(splitDocs)` 输出是一大坨文本，像是整个文档。

**原因**：两件事叠加。`Document.String()` 返回 Content；切片打印时元素之间用空格连接。所以"每片一行"的边界被空格粘住了，反而片内真正的换行还留着。

**解决**：改成逐片打印，内容用 `%q` 输出，换行以 `\n` 形式显示。

### 问题 2：仓库根目录凭空出现空的 document.md

**现象**：`git status` 里多出未跟踪的 `document.md`，0 字节。

**原因**：代码里有一句 `os.OpenFile("./document.md", os.O_CREATE|os.O_RDWR, 0775)`。路径是相对 cwd 的，在仓库根目录跑过一次，就在根目录创建了这个空文件。而这个 OpenFile 拿到的句柄根本没被用过，真正读取用的是 `os.ReadFile`。

**解决**：删掉整段 OpenFile，只留 `os.ReadFile`。

### 问题 3：02_streaming_chat 启动就 panic

**现象**：

```text
panic: new client fail, missing credentials: set 'APIKey' or both 'AccessKey' and 'SecretKey'
```

**原因**：`godotenv.Load(".env")` 用的是相对路径，`.env` 实际在仓库根目录，从 `demos/02_streaming_chat` 启动时找不到文件；错误又被 `_ =` 丢掉了，于是 `ARK_API_KEY` 是空字符串，创建 Ark 客户端时失败。同目录的 01、04 用的是绝对路径，所以没事。

**状态**：尚未修复。

## 容易混淆

- `Document.String()` ≠ 打印整个文档结构，它只给 Content
- `schema.Document` 的 MetaData（业务元数据）和 Milvus 里的 metadata 字段是两处概念，别混
- 切分产生的"只有标题的片"不是 bug
- `%T` 打印的是**动态**类型：`map[string]any` 取出来的值 `%T` 显示 `string`，但它的静态类型是 `any`
- `%v` 打印切片是用空格连接元素的，元素有 `String()` 方法时会用该方法——所以 `fmt.Println(splitDocs)` 看着像一整块

### 封装时改掉的两个问题

**1. 组件不再自己终止进程。** 原来 5 个构造函数里用的是 `log.Fatalf` / `panic`，任何一个失败整条链就没了，调用方拿不到 error。改成全部返回 `error`，用 `fmt.Errorf("...: %w", err)` 包装保留错误链；"失败就退出"这个决定交给程序顶层（`RAG/Rag.go` 里的 `log.Fatalf`）去做。

**2. 流式消费开始区分 `io.EOF` 和真错误。** 原 demo 写的是：

```go
chunk, err := reader.Recv()
if err != nil {
    break // 流结束或出错时退出循环
}
```

eino 官方文档里明确写了 `Recv` 返回 `io.EOF` 表示**流正常结束**（`schema/stream.go:131`）。只判断 `err != nil` 会把正常结束和网络中断、鉴权失效混在一起，失败被静默当成"生成完了"。封装后的写法：

```go
for {
    chunk, err := reader.Recv()
    if errors.Is(err, io.EOF) {
        return nil // 流正常读完
    }
    if err != nil {
        return fmt.Errorf("读取流失败: %w", err) // 真出错
    }
    ...
}
```
