## 真正理解的知识

### 1. 静态类型 = 编译期确定 + 编译器强制检查

对照关系：

| | 类型什么时候确定 | 传错了什么时候发现 |
|---|---|---|
| Python（动态类型） | 运行期 | 跑到那一行才报错 |
| Go（静态类型） | 编译期 | `go build` 就报错，不用运行 |

那句话是**拿来跟 Python 系框架（LangChain / LlamaIndex）做对比的**，不是单纯在夸 Go。

直觉比喻：动态类型像没有形状约束的插座，说明书在文档和别人的博客里，插错才知道；静态类型像插头和插座有形状，不对就插不进去。**函数签名就是那个形状**。

### 2. 接口签名本身就是说明书

`eino@v0.9.19/components/document/interface.go:53`：

```go
type Transformer interface {
	Transform(ctx context.Context, src []*schema.Document, opts ...TransformerOption) ([]*schema.Document, error)
}
```

只看这一行就知道入口是 `Document` 切片、出口也是 `Document` 切片，不用查文档、不用猜。

同类的还有：

- `components/retriever/interface.go:48` —— `Retrieve(ctx, query string, opts ...Option) ([]*schema.Document, error)`
- `components/indexer/interface.go:38` —— `Store(ctx, docs []*schema.Document, opts ...Option) (ids []string, err error)`

在 Python 里，`chain.invoke()` 该传 dict、传 str 还是 `HumanMessage`，签名上完全不体现——这就是"心智负担"的具体形态。

### 3. 类型衔接是链路能串起来的前提

`RAG/rag.go` 里三段代码能直接接起来，靠的是类型吻合：

```go
splitDocs, err := transform.Transform(ctx, []*schema.Document{doc}) // 出口 []*schema.Document
ids, err := indexer.Store(ctx, splitDocs)                          // 入口正好相同
results, err := retriever.Retrieve(ctx, "海鸥")                     // 出口也是 []*schema.Document
```

链上任何一环类型不匹配，都是在 `go build` 阶段断开。

对应到 `tool/tool.go`：`NewTool[T, D any]` 里的 `T = *InputParams`、`D = string` 是编译器从 `GetWeather` 签名推断出来的（泛型机制见 `docs/go/generics.md`）。**泛型负责编译期把具体类型接上，接口负责运行期给框架统一入口。**

### 4. 关键：静态类型的边界在哪里

这是今天最有价值的一点。**静态类型不是"消灭运行期错误"，而是把检查推到编译期能推的最远处，剩下的部分明确标出来。**

`main.go` 里就有现成的边界：

```go
params := map[string]any{"role": "编程助手", "task": "golang的优势"}
messages, err := template.Format(ctx, params)
```

`Format` 的签名是（`components/prompt/interface.go:44`）：

```go
Format(ctx context.Context, vs map[string]any, opts ...Option) ([]*schema.Message, error)
```

模板里写的是 `{role}`。如果把 key 拼成 `"roles"`：

- **编译完全通过**
- 运行期模板变量填不上

因为编译器只知道 value 是 `any`，不知道这个 map 里有没有 `role`。这正是 [Go fmt](../go/fmt.md) 里学的那个区分的实际后果：`any` 的静态类型是 `any`，装什么要运行期才知道。

同样的边界在工具调用处——框架面向模型暴露的入口是 JSON 字符串（`components/tool/interface.go`）：

```go
InvokableRun(ctx context.Context, argumentsInJSON string, opts ...Option) (string, error)
```

模型吐出来的 JSON 是运行期数据，静态类型在这一步必须让位。所以手工传给 `NewTool` 的 `*schema.ToolInfo` 和 `T` 的字段是否一致，编译器**不检查**——这也是 `InferTool` 存在的理由。

## 容易混淆

- **静态类型 vs 强类型是两根轴**。Go 是静态类型、Python 是动态类型，但两者都是**强类型**（`1 + "a"` 在两边都不让过）。静态/动态说的是"什么时候检查"，强/弱说的是"检查多严"。
- **静态类型不排斥动态**。Go 的 `any` 和接口就是可控的动态；`any` 用得越多，手感越接近动态语言，代价是回到运行期报错。
- **"Go 编译期检查"和"图编排检查"不是一回事**。`compose.NewGraph[I, O any]()` 的输入输出类型是编译期确定的（`compose/generic_graph.go:72`），但节点之间"上游输出类型必须等于下游输入类型"这个检查是 `AddEdge` / `Compile` 阶段**返回 error** 检查的，不属于 Go 编译期。
- **动态类型 ≠ 弱类型，静态类型 ≠ 纯粹啰嗦**。写 struct、处理 error 这些"啰嗦"换来的正是上面那张表里的每一项负担被消除。

## 还没理解

- Python 系框架的"心智负担"具体长什么样——目前是从 Eino 官方介绍里得到的二手信息，没有实际用过 LangChain

## 今天的关键结论

> 静态类型 = 类型在编译期确定并被编译器强制检查。Eino 的做法是：组件与组件之间靠编译期类型衔接，一旦进入 `any` / JSON 这类必须动态的边界，就用 `any` 明确标出来，代价是那部分检查推迟到运行期。

## 下午：Chain 编排（orchestration/chain/chain.go）

第一次用 Chain 把「Lambda 加工 → ChatModel」串成一条链：

```go
lambda := compose.InvokableLambda(
	func(ctx context.Context, input string) (output []*schema.Message, err error) {
		content := input + "回答结尾加上 今天天气很好"
		output = []*schema.Message{{Role: schema.User, Content: content}}
		return output, nil
	})

chain := compose.NewChain[string, *schema.Message]()
chain.AppendLambda(lambda).AppendChatModel(model)

r, err := chain.Compile(ctx)
answer, err := r.Invoke(ctx, "你好，请告诉我你的名字")
fmt.Println(answer.Content)
```

跑通输出：`你好，我的名字是DeepSeek。今天天气很好。`——Lambda 把两句话拼成一条 user 消息，模型把后半句当指令执行了。

### 关键规则（实测验证过）

**`NewChain[I, O]` 的 `I` 必须等于第一个节点的输入类型，`O` 必须等于最后一个节点的输出类型。**

反例（能编译、能过 vet，但 `Compile` 时 panic）：

```go
chain := compose.NewChain[string, *schema.Message]()
chain.AppendChatModel(model) // ChatModel 的输入是 []*schema.Message，接不上 string
```

```text
panic: graph edge[start]-[node_0]: start node's output type[string] and end node's input type[[]*schema.Message] mismatch
```

这是「静态类型有边界」的又一个实例：**类型参数写错 Go 编译期查不出来，要等 `Compile(ctx)` 返回 error**。

两种改法都实测可用：A 把 `I` 改成 `[]*schema.Message` 并让 `Invoke` 传消息切片；B 保留 `string` 输入，前面加一个 Lambda 做转换。`chain.go` 用的是 B。

### debug 记录：`orchestration/chain/chain.go` 跑不起来

**现象**

```text
$ go run ./orchestration/chain/
package maxenio/orchestration/chain is not a main package
```

**原因（4 个问题，只有第 1 个真的卡住运行）**

1. **`package mian` 和 `func mian()` 两个拼写错误。** `package mian` 让这个目录被当成普通库包，不是 main 包，所以 `go run` 直接拒绝；就算包名对了，`func mian()` 也不是入口函数。→ 改成 `package main` / `func main()`。
2. **`model, err := components.NewarkModel(ctx)` 之后没检查 err。** `NewarkModel` 失败会返回 `nil, err`，nil 的 `*ark.ChatModel` 塞进 `AppendChatModel` 后，问题会以 nil 指针 panic 的形式冒出来，而不是明确告诉你"创建 model 失败"。→ 补上 err 检查。
3. **局部变量 `context` 遮蔽了 `context` 包名。** 能编译，但同一个函数里再想写 `context.Context` 就用不了了。→ 改名 `content`。
4. **没有 gofmt。** 第 34-35 行缩进错位。→ `gofmt -w`。

**验证**

```text
$ go vet ./orchestration/chain/ && gofmt -l orchestration/   # 都干净
$ go run ./orchestration/chain/
你好，我的名字是DeepSeek。今天天气很好。
```
